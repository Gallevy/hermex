## Findings considered and rejected

- **Plan 009 (TypeScript RC pin)**: REMOVED by maintainer decision 2026-07-03 — the TS 7.0.1-rc pin is intentional; plan file deleted.

- **SEC-01/02** (dynamic config import / path traversal in --config): By design. This is the standard vite/eslint/prettier pattern for config files; the user runs their own code in their own process. Not a finding for a local CLI tool.
- **SEC-05** (js-yaml `load()` unsafe): False positive. js-yaml v4+ `load()` is safe by default; the unsafe functions were removed. pnpm v9 lockfiles are YAML, not user-controlled arbitrary input.
- **SEC-04** (glob pattern ReDoS): Low confidence. `micromatch` does not use catastrophic-backtrack regex patterns.
- **DEP-05** (chalk/ora/cli-table3 in `dependencies` instead of `devDependencies`): By design. hermex is a CLI tool; these are runtime dependencies needed when the binary runs.
- **DEBT-04** (vitest config missing): False positive. `vitest.config.ts` exists at the repo root.
- **TEST aggregator full coverage** (beyond Plan 006 scope): Plan 006 covers the critical paths. Complete coverage of edge cases (multi-version conflict, scoped package resolution variants) can be added incrementally.
- **PERF-05 (visitChildren for...in)**: Standard visitor pattern — `for...in` checks `value.type` before recursing, so it only visits AST nodes. Changing to a whitelist would be fragile. By design.
- **BUG-07 (JSX double processing)**: `analyzeJSXOpeningElement` is called twice per JSXElement but the second call is rejected by the Map guard (`if (!jsxUsage.has(...))`). No correctness impact. Not worth a plan.
- **LOGIC-04 (null concatenation in extractAssignmentInfo)**: `"null.PropertyName"` string is never in `componentNames`, so it's discarded immediately by `isKnownComponent`. Harmless in practice.
- **LOGIC-02 (jsxUsage only stores first JSX occurrence)**: By design — the Map is keyed by component name, storing first-seen props. This is a deliberate design choice for the current data model.
- **allow_files semantics**: `allow_files` and `require_files` both produce violations on zero matches. Whether this is a bug or by-design requires clarification from the maintainer. Medium confidence — not planned.
- **engine-version prerelease false positive**: `semver.minVersion(">=18.0.0-rc.1")` returns `18.0.0-rc.1` which does not satisfy `>=18.0.0`. Edge case for unusual engine ranges. Low priority.
- **pnpm regex non-semver**: `/\/(.+?)\/(\d+\.\d+\.\d+.*?)(?:_|$)/` only matches v6-8 format; workspace packages fail silently. Very edge case in practice.
- **isFromLibrary substring matching**: `source.includes(libraryName)` can match unintended paths. Low confidence — depends on what users pass as libraryName.
- **format-utils/chart-renderer unit tests**: Pure display code with simple logic. Low test value given the complexity of writing good tests for terminal output.
